# Git Practice

## Article

[Is High Quality Software Worth the Cost?](https://martinfowler.com/articles/is-quality-worth-cost.html) by Martin Fowler

## My Thoughts

I found this article interesting because it challenges the idea that writing cleaner code always slows development down. Fowler explains that well-organized code makes future changes easier, which can save time as a project grows. This makes sense to me because completing one feature quickly is less helpful if the next developer struggles to understand the code. It makes me think about how my coding choices could affect other people working on the same project.

Another point that stood out to me is that even experienced teams need to improve their code as they learn more. I especially like the idea that good design develops over time instead of being perfect from the beginning. For a team project, I would pay attention to clear names and readable code. I also wonder how a team should decide which improvements are worth making when a deadline is close.



\## Comment from Tony



You ask how to balance code cleanup with a tight deadline. I think Fowler gives a clear answer. He says good internal code quality can start saving time within a few weeks, not months. So even when the deadline is close, saying “we don’t have time to do it properly” may not always be true.



I would also add that when an AI agent writes a lot of the code, readable code becomes even more important. If the code is hard to understand, it is also hard to review. In that case, bad code can cause problems very quickly, not months later.
